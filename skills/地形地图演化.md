# Skill 框架：3DWorldMapGenerationSkill

## 1. Skill 目标

该 Skill 用于通过 **程序化算法 + LLM Loop** 生成 3D 游戏世界地图。

核心功能：

```text
1. 读取编辑器已有地形高度、水域信息
2. 读取可用资源模型信息
3. 对模型体型、放置条件、地形影响进行预评估
4. 根据地形、水域、生物群系、文明发展逻辑生成地图内容
5. 使用 LLM Loop 对生成结果进行合理性、美观性、玩法性评估
6. 根据评分自动或半自动调整地图
7. 最终导出可被编辑器使用的地图生成数据
```

# 5. 世界生成阶段框架

## 阶段 0：资源扫描与预评估

```text
目标：
读取所有可用资源模型，建立资源数据库。

输入：
- 动物模型
- 植被模型
- 建筑模型
- 人形角色模型
- 怪物模型
- Boss 模型
- 装饰物模型

输出：
- asset_registry.json
- asset_profiles.json
- asset_terrain_effects.json
- asset_performance_profiles.json
```

---

## 阶段 1：地形读取与分析

```text
目标：
读取编辑器已有地形高度和水域数据，生成地形分析图层。

输入：
- 高度图
- 水域图
- 地图尺寸
- chunk 配置

输出：
- heightmap_snapshot.json
- watermap_snapshot.json
- slope_map.json
- buildable_area_map.json
- region_map.json
- biome_map.json
```

---

## 阶段 2：基础自然区域生成

```text
目标：
根据地形、水域、高度、坡度生成自然区域。

生成内容：
- 山地
- 丘陵
- 平原
- 森林
- 草原
- 沼泽
- 沙漠
- 雪地
- 河谷
- 湖区
- 海岸
- 特殊自然区域

输出：
- natural_regions.json
- biome_map.json
```

---

## 阶段 3：生态生成

```text
目标：
根据自然区域生成植被、动物和基础生态链。

生成内容：
- 植被分布
- 动物分布
- 资源分布
- 生态密度
- 危险度
- 迁徙路径

输出：
- ecology_layer.json
- vegetation_placement.json
- animal_spawn_zones.json
```

---

## 阶段 4：怪物与 Boss 区域生成

```text
目标：
根据地形、生态、危险度和资源模型生成怪物区域。

生成内容：
- 普通怪物巢穴
- 精英怪区域
- Boss 区域
- 禁区
- 地下入口
- 特殊战斗区域

输出：
- monster_zones.json
- boss_areas.json
- danger_map.json
```

---

## 阶段 5：文明与建筑生成

```text
目标：
根据水源、地形、资源、道路和安全度生成智慧生物活动区域。

生成内容：
- 村庄
- 城镇
- 营地
- 要塞
- 道路
- 桥梁
- 农田
- 矿场
- 港口
- 遗迹
- 装饰物

输出：
- settlements.json
- roads.json
- building_placement.json
- decoration_placement.json
```

---

## 阶段 6：LLM Loop 评估与修正

```text
目标：
用 LLM 对当前世界状态进行合理性、美观性、玩法性评估，并生成修改建议。

输入：
- 区域摘要
- 资源摘要
- 当前世界状态
- 硬规则评分
- 性能评分

输出：
- llm_evaluation_report.json
- patch_plan.json
```

---

## 阶段 7：验证、修复与冻结

```text
目标：
执行硬规则检查、自动修复、最终冻结地图。

检查内容：
- 模型是否放置在合理地形
- 模型体型是否与地形空间匹配
- 是否发生重叠
- 是否有不可达区域
- 是否超出性能预算
- 怪物与村庄距离是否合理
- Boss 区域是否有足够战斗空间
- 道路是否连通
- 生态是否冲突

输出：
- final_world_state.json
```

---

## 阶段 8：导出

```text
目标：
导出可供游戏编辑器使用的数据和脚本。

输出：
- final_world_state.json
- asset_placement.json
- spawn_points.json
- road_data.json
- settlement_data.json
- editor_generation_script
- performance_report.json
- final_summary.md
```

# 7. LLM Loop 运行框架

## 7.1 总循环

```text
Start
  ↓
读取世界状态
  ↓
生成区域摘要
  ↓
运行硬规则评分
  ↓
如果硬规则不通过：
    自动修复或重生成
  ↓
调用 LLM 评估
  ↓
LLM 输出评分和问题
  ↓
如果评分 >= 阈值：
    进入下一阶段或冻结
  ↓
如果评分 < 阈值：
    LLM 输出 Patch Plan
  ↓
程序解析 Patch Plan
  ↓
执行可控修改
  ↓
重新验证
  ↓
进入下一轮
End
```

# 8. LLM 在 Skill 中的职责边界

## LLM 负责

```text
1. 根据模型描述评估资源适用环境
2. 判断区域生态是否合理
3. 判断文明发展是否合理
4. 判断怪物/Boss 区域是否有叙事和玩法合理性
5. 判断地图是否美观、丰富、有探索价值
6. 生成区域修改建议
7. 生成区域命名、背景、风格标签
8. 生成 Patch Plan
```

---

## 程序脚本负责

```text
1. 读取高度和水域
2. 计算坡度、距离、连通性
3. 区域划分
4. 具体坐标放置
5. 碰撞检查
6. 性能预算检查
7. 道路寻路
8. 模型密度控制
9. 资源实例化
10. 导出编辑器脚本
```

analyze_buildable_area.py
用途：
根据高度、坡度、水域、空间判断建筑可放置区域。

# 14. 总结框架

最终这个 Skill 可以按下面这个主流程运行：

```text
1. 扫描资源
2. 记录模型体型
3. 评估模型适宜地形
4. 评估模型对地形影响
5. 评估模型性能消耗
6. 读取编辑器地形和水域
7. 分析高度、坡度、水域距离
8. 划分区域和生物群系
9. 生成植被、动物、怪物、Boss
10. 生成村庄、建筑、道路、装饰物
11. 运行 LLM Loop 评估
12. 根据 Patch Plan 修复地图
13. 多轮迭代直到评分达标
14. 冻结地图
15. 导出最终世界状态和编辑器脚本
```

核心原则：

```text
LLM 负责判断、规划、解释、修正建议。
脚本负责计算、放置、验证、导出。
编辑器负责最终地形、水域和资源实例化。
```
