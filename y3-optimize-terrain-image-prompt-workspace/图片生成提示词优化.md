# Y3 图片转地形专用提示词优化器

## 目标

本 Skill 的目标是：在不改变用户原始地图设计意图的前提下，将用户的自然语言描述改写成一组适合文生图模型使用的提示词，使生成的图片更适合后续 `y3-gen-terrain-from-image` 进行 CV + AI 识别。

本 Skill 生成的图片提示词应优先服务于以下目标：

1. 地形边界清晰；
2. 水域、陆地、山地、森林、道路等语义明显；
3. 高度信息更容易被识别；
4. 干扰项更少；
5. 图片边界与最终地图边界 1:1 对应；
6. 尽量避免艺术化光影、透视、复杂纹理和装饰；
7. 便于后续色彩聚类、水域识别、大陆分割、纹理分配、高度推断和装饰物识别。

本 Skill 不负责生成图片。  
本 Skill 不负责调用 Y3 MCP。  
本 Skill 不负责写入地形。  
本 Skill 只负责将用户原始地图描述优化为适合“图片转地形”的文生图提示词。

---

## 适用场景

当用户只有文字描述，还没有地图图片时，应使用本 Skill。

典型场景：

- 用户希望先通过文生图模型生成一张地图图片；
- 用户希望这张图片后续能被 `y3-gen-terrain-from-image` 更好识别；
- 用户要求“不要生成好看的图，而是生成适合还原成 Y3 地形的图”；
- 用户要求“优化地图生成提示词”；
- 用户要求“让 AI 生成的地图图片更适合图片转地形”。

示例触发语句：

```text
帮我优化一段地图生成提示词，用于图片转地形。

## 输入

1. 原始地图描述；
2. 游戏类型；

## 核心原则

### 1. 不改变用户原意

必须保留用户原始描述中的核心设计意图，包括：

- 地图主题；
- 地貌类型；
- 主要区域关系；
- 阵营或出生点布局；
- 道路、河流、桥梁、山脉的位置关系；
- 特殊玩法需求；
- 用户明确要求保留的风格。

可以增加“机器可读性约束”，但不能擅自新增会改变地图结构的元素。

错误示例：

用户原意：

```
一个中央湖泊，四周是森林和丘陵。
```

错误优化：

```
一个中央火山，四周是岩浆，森林被烧毁。
```

错误原因：

```
改变了核心地貌和地图结构。
```

正确优化：

```
一张俯视正交地形规划图，中央是边界清晰的蓝色湖泊，湖泊四周分布深绿色森林和浅棕色丘陵，区域边界清楚，色块简洁，适合后续图片转地形识别。
```

---

### 2. 生成“地形规划图”，不是“风景插画”

必须引导文生图模型生成：

- top-down view；
- orthographic view；
- flat terrain planning map；
- clean map layout；
- no perspective；
- no cinematic lighting；
- no realistic landscape painting。

优先使用这些表达：

```
俯视图、正交视角、地形规划图、游戏地图草图、机器可读、清晰色块、低纹理噪声、边界清晰、无透视、无阴影
```

避免使用这些表达：

```
电影感、超真实、氛围光、景深、日落、云雾、写实摄影、复杂纹理、精美插画
```

---

### 3. 地貌颜色必须有明确语义

应尽量指定稳定的颜色语义，方便 CV 聚类和 AI 识别。

推荐颜色规范：

| 地貌      | 推荐颜色                |
| ------- | ------------------- |
| 深水      | 深蓝色                 |
| 浅水      | 青蓝色                 |
| 沙滩 / 岸边 | 浅黄色                 |
| 平原      | 浅绿色                 |
| 森林      | 深绿色                 |
| 丘陵      | 橄榄绿或浅棕色             |
| 山地      | 棕色 / 灰棕色            |
| 高山 / 雪峰 | 灰白色或白色              |
| 道路      | 浅土黄色                |
| 桥梁      | 浅棕色或木色              |
| 沼泽      | 暗绿偏蓝                |
| 荒地      | 土黄色 / 灰黄色           |
| 火山 / 熔岩 | 黑灰色 + 红橙色，仅在用户要求时使用 |

注意：

- 颜色只作为提示词约束，不要求输出具体调色板文件；
- 不要为了追求视觉美观而使用大量渐变、纹理和光影；
- 色彩应稳定、区域应清晰，优先服务于后续识别。

---

### 4. 高度信息必须清晰表达

如果用户描述中包含山地、高地、峡谷、盆地、丘陵、台地、雪山、火山等高度相关元素，必须增加高度可识别提示。

推荐方式：

1. 使用离散高度色带；
2. 使用从低到高的颜色层级；
3. 山脉中心更高、边缘逐渐降低；
4. 河流、湖泊和海岸保持最低；
5. 丘陵用浅棕色或橄榄绿色缓坡区域表达；
6. 高山用棕色到灰白色渐进表达；
7. 可使用少量无文字等高线，但不能密集。

推荐提示：

```
高度通过清晰的离散色带表达，低地为浅绿色，丘陵为浅棕色，山地为棕色，高山为灰白色，水域为最低深蓝色；山脉从边缘到中心逐渐升高，形成容易识别的高度层级。
```

不推荐：

```
强烈阴影表现山体高度。
```

原因：

```
阴影会干扰色彩聚类，导致水域、森林、山地、高度区域识别错误。
```

---

### 5. 禁止文字、图例、罗盘和 UI 元素

除非用户明确要求，否则必须在负向提示词中禁止：

- 文字；
- 数字；
- 图例；
- 罗盘；
- UI 面板；
- 网格线；
- 坐标轴；
- 水印；
- 地名标签；
- 路标文字；
- 装饰边框。

原因：

```
这些元素会干扰 CV 聚类、水陆分割、纹理识别、装饰物识别和高度推断。
```

---

### 6. 减少装饰噪声

如果用户没有明确要求，不要加入太多：

- 小房子；
- 人物；
- 怪物；
- 船只；
- 车辆；
- 云；
- 旗帜；
- 城墙花纹；
- 图标；
- 大量碎石；
- 大量小树单体；
- 复杂建筑群。

森林应该优先表现为清晰的深绿色区域，而不是大量独立树冠图标。

山脉应该优先表现为清晰的棕色、灰棕色、灰白色高度区域，而不是大量写实山峰插画。

村庄、基地、资源点可以用简洁区域表示，但不应变成复杂建筑插画。

---

### 7. 保持地图边界与画面边界一致

必须加入以下要求：

```
地图内容填满整个画布，地图边界与图片边界严格对齐，不要倾斜，不要留白边，不要装饰相框。
```

原因：

```
后续图片转地形通常会将图片坐标映射到编辑器地图网格，因此图片边界应与地图边界 1:1 对应。
```

---

### 8. 控制风格

优先推荐以下风格：

```
简洁战略地图风格
平面地形规划图风格
游戏关卡设计俯视图
低噪声色块风格
清晰区域分割
机器可读地图
```

如果用户要求奇幻、科幻、写实、卡通等风格，可以保留主题，但必须弱化视觉装饰。

示例：

用户要求：

```
奇幻风格岛屿地图。
```

优化时应变成：

```
奇幻主题的俯视正交地形规划图，但保持区域色块清晰、无复杂插画、无文字、无装饰边框，优先服务于图片转地形识别。
```

## 工作流程

### Step 1：提取用户原始意图

从用户输入中提取：

- 地图主题；
- 地形元素；
- 区域布局；
- 高度元素；
- 水域元素；
- 道路 / 桥梁 / 路径；
- 特殊玩法点；
- 风格要求；
- 禁止改变的内容。

如果用户描述模糊，不要过度追问，使用通用机器可读约束补齐。

---

### Step 2：判断是否需要高度提示

如果用户输入中出现以下词语，应加入高度识别提示：

```
山、山脉、高山、雪山、丘陵、峡谷、盆地、高原、台地、悬崖、火山、河谷、坡地、山谷、峭壁、低地
```

如果没有高度相关词，则只添加基础高度友好约束：

```
整体地势层级清楚，水域最低，平原较低，丘陵和山地区域使用不同颜色区分。
```

---

### Step 3：构造正向提示词

正向提示词结构必须包含：

```
[地图主题与用户原意]
[俯视正交与地形规划图要求]
[地貌元素与布局]
[颜色语义]
[高度表达方式]
[边界与构图要求]
[低噪声和机器可读要求]
```

---

### Step 4：构造负向提示词

负向提示词必须包含：

```
透视视角、斜视角、3D场景、电影感光照、强阴影、复杂纹理、写实摄影、景深、云雾、文字、数字、地名、图例、罗盘、UI、水印、装饰边框、人物、怪物、车辆、大量小图标、过度细节、随机噪点、模糊边界
```

可根据用户内容适当补充。

---

### Step 5：输出可选参数建议

如果用户没有指定模型，给通用建议：

```
画幅：1:1 或与目标地图比例一致
风格：flat map / orthographic map / terrain planning map
清晰度：高
细节：中低
写实程度：低
随机性：中低
```

如果是 Stable Diffusion 类模型，可建议：

```
CFG：5~7
Steps：25~35
Denoise：中低
Sampler：DPM++ 2M Karras 或同类稳定采样器
```

如果是 Midjourney 类模型，可建议：

```
--style raw
--ar 1:1
较低 stylize
```

不得强制用户使用某个具体模型。
