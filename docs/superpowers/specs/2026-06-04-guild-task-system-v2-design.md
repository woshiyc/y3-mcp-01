# 冒险者公会任务系统 V2 设计文档

**日期**：2026-06-04
**项目**：类Majesty俯视角领地管理游戏（Y3引擎）
**状态**：待实现
**前置文档**：[docs/superpowers/specs/2026-06-03-adventurer-guild-task-system-design.md](2026-06-03-adventurer-guild-task-system-design.md)

---

## 1. 变更背景

本文档对 V1 设计进行三处核心修订：

1. **任务执行从概率模型改为实时模拟** — 角色是有属性/技能/行为树的 MOBA 单位，接任务后在地图上实际执行，成功/失败由目标达成与否决定
2. **等级接受范围引入难度系数** — 高等级角色在不同游戏难度下对低等级任务的容忍幅度不同；低等级角色接高等级任务不受限制
3. **删除忠诚度，改为特质系统** — 任务结果、伤亡、放弃等事件触发特质判定，特质同时影响战斗数值和任务接受行为

V1 中所有与概率失败计算、忠诚度相关的内容以本文档为准覆盖。

---

## 2. 任务执行模式

### 2.1 实时模拟（替换概率模型）

派遣确认后，冒险者单位出现在游戏地图上，由行为树驱动自主行动：

| 结果 | 触发条件 |
|------|---------|
| **成功** | 任务目标达成（击杀数 / 采集量 / 护送到达等） |
| **主动放弃** | 玩家主动召回，立即触发负面特质判定，按失败结算 |
| **战斗失败** | 所有参与角色全部倒地（单人：1人倒地；多人：全员倒地） |

> `quest_dispatch.lua` 中的失败概率计算层整体删除。`quest_execution.lua` 改为监听目标达成事件和角色死亡事件。

### 2.2 装备影响

装备不再修正失败概率，改为直接影响角色战斗属性（攻击力、护甲、技能冷却等），效果通过行为树实际体现。

## 3. 伤亡判定系统（新增 `casualty.lua`）

### 3.1 单人任务伤亡判定链

```
角色 HP = 0
  └─→ 伤亡判定 Roll（基础成功率见3.5）
        ├─ 通过（存活）→ 进入【修养状态】→ 触发休假判定 + 负面特质判定
        └─ 失败（阵亡）→ 移入墓地，永久移除 → 任务失败
```

### 3.2 多人任务伤亡判定链

单个角色倒地时，**立即**按以下顺序处理，处理完毕后检查全队是否倒地，再处理下一个倒地事件：

```
角色 HP = 0（立即触发）
  └─→ 队内有存活的牧师？
        ├─ 是 → 急救判定 Roll（成功率见3.5）
        │         ├─ 急救成功 → 进入【修养状态】，无法继续本次任务
        │         │             （任务结束后统一触发特质/休假判定）
        │         └─ 急救失败 → 伤亡判定 Roll（同单人链）
        └─ 否 → 伤亡判定 Roll（同单人链）

每次单角色处理完毕后检查：
  全队均已倒地或死亡？ → 任务失败
  否 → 继续任务
```

> **主动放弃在多人任务中的定义**：玩家召回视为全队主动放弃，不支持部分召回。召回操作只能针对整支队伍，触发时所有仍在场角色统一按主动放弃结算。

### 3.3 任务结束后统一触发

| 情境 | 特质触发 |
|------|---------|
| 任务成功 | 正面特质 Roll + 负面特质 Roll（各独立，成功也可能留下心理创伤） |
| 任务失败（战斗） | 负面特质 Roll |
| 主动放弃 | 负面特质 Roll（触发概率比战斗失败更高） |
| 本次修养角色 | 额外负面特质 Roll |
| 旁观全灭的在场成员 | 负面特质 Roll（替代原"旁观者 -20 忠诚度"） |

### 3.4 状态说明

| 状态 | 含义 | 持续时间 |
|------|------|---------|
| **修养** | 受重伤，角色存活但无法接任务 | 2~4 游戏日（初稿固定值，后期可按伤势分档） |
| **休假** | 心理/身体休整，不愿接任务 | 修养结束后触发 Roll：50% 进入休假 1~2 游戏日 |

### 3.5 数值占位（待精调）

| 判定 | 基础成功率 | 修正来源 |
|------|----------|---------|
| **伤亡判定**（存活） | 60% | +「九死一生」+10%；+「坚韧」+5%；-「脆弱」-10%；角色等级每高于任务等级1档 +5% |
| **急救判定**（牧师） | 50% | +牧师等级每高于伤者等级1档 +10%；+「坚韧」特质 +15%（牧师自身） |

> 以上数值为初稿占位，实装时通过测试调整。角色等级/任务等级的具体映射沿用 V1 整数值体系（F=1 … S=7）。

## 4. 等级接受范围系统

### 4.1 核心公式

每个角色的可接任务等级区间为 **[下限, 上限]**：

- **默认上限**：无上限，任何角色均可报名高于自身等级的任务（风险自担）
- **「懦弱」特质上限例外**：持有「懦弱」时，上限 = 自身等级整数值（即不接超过自身等级的任务）
- **「无畏」特质**：明确无视上限（等同默认行为，但额外赋予 AI 倾向高等级任务的优先级权重）
- **下限** = 自身等级整数值 − 难度容忍幅度 + 特质等级修正（下限最小为 1）

### 4.2 难度容忍幅度表

| 游戏难度 | 容忍幅度 | S级（整数值7）可接最低等级 |
|---------|---------|------------------------|
| 简单 | 4 | D 级（整数值 3） |
| 普通 | 3 | C 级（整数值 4） |
| 困难 | 2 | B 级（整数值 5） |
| 噩梦 | 1 | A 级（整数值 6） |
| 地狱 | 0 | 只接 S 级（整数值 7） |

> F/E 级角色的下限计算结果若 ≤ 1，则等同于无下限限制（可接 F 级及以上任何任务）。

### 4.3 特质对等级幅度的修正

特质可扩大或收窄可接范围（效果叠加，见 Section 5）：

| 特质 | 等级幅度效果 |
|------|------------|
| 「骄傲」 | 下限额外 +1（更挑剔） |
| 「贪财」 | 下限额外 -1（愿意接低等级任务刷赏金） |
| 「懦弱」 | 上限 -1（不接超过自身等级的任务） |
| 「无畏」 | 无视上限限制，且主动倾向高等级任务 |

### 4.4 报名门槛（更新 `quest_board.lua`）

原三重门槛更新为：

```
1. 等级范围检查：任务等级整数值 在 [下限, 上限] 内？
   → 否则拒绝
2. 空闲检查：当前无任务、不在修养/休假状态？
   → 否则拒绝
3. 特质行为检查：是否持有"拒绝此类任务"的特质？
   → 否则拒绝
4. 全部通过 → 报名
```

> 赏金倍率不再是强制门槛，改为影响报名意愿的权重（高赏金任务优先排队），不强制阻断报名。

## 5. 特质系统（替换忠诚度）

### 5.1 特质列表结构

每个角色持有一个**特质列表**（上限 6 条）：

```lua
-- 单条特质数据结构
{
  id       = "PTSD",          -- 唯一标识
  name     = "应激障碍",
  type     = "negative",      -- "positive" / "negative"
  removable = true,            -- 是否可自然消除
  effects  = {
    stat_mod   = { hp_max = -0.1 },  -- 数值修正（可选）
    behavior   = { reject_quest_type = {"hunt"} }, -- 行为限制（可选）
    level_mod  = { min_offset = 0 },  -- 等级幅度修正（可选）
  }
}
```

### 5.2 特质触发判定

触发时从对应池（正面/负面）中随机抽取一条尚未持有的特质，Roll 决定是否真正获得：
- **基础触发率**：负面 40%，正面 25%（任务成功时的正面 Roll）
- **特质上限已满（6条）且存在可消除特质**：先随机消除一条 `removable = true` 的旧特质，再抽取新特质
- **特质上限已满且全部不可消除**：本次特质触发取消，不做任何操作（新特质被阻断，记录日志供调试）

| V1 系统 | V2 替换方案 |
|---------|-----------|
| `adventurer_data.lua` `loyalty` 字段 | 删除，改为 `traits[]` 列表 |

| 全灭旁观者 -20 忠诚度 | 旁观者触发负面特质 Roll |
| 闲置每游戏日 -3 忠诚度 | 删除（无对应替换，简化系统） |

## 6. 模块改动清单

| 模块 | 改动类型 | 主要变更 |
|------|---------|---------|
| `adventurer_data.lua` | 修改 | 删除 loyalty，新增 traits[]、状态字段（resting/vacation） |
| `quest_board.lua` | 修改 | 重写等级门槛逻辑，引入难度容忍幅度；删除忠诚度门槛 |
